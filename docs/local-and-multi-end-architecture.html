工业试验箱平台：本机与多端部署方案

生产环境中，通讯工程师提供的 C++ 应用层是实时数据共享内存的唯一写入方。每台工控机仅保留一个 Python 后端服务：设备边缘服务（device_edge），负责读取数据、服务本机 Vue Web、管理内嵌 SQLite，并按需上传和接收总控命令。

一个本地后端进程
device_edge 将共享内存读取、本机 API、命令桥接、内嵌 SQLite 和可选总控同步组织在一个服务内，降低工控机 CPU、内存与运维负担。
仍然前后端分离
Vue Web 通过 HTTP / WebSocket 调用 device_edge；前端不读取共享内存、不处理设备协议。
C++ 拥有设备侧事实
C++ 写入实时数据内存、读取命令请求并写入执行结果。device_edge 不生成或篡改设备实时数据。

方案 A：仅本机显示与控制

适用于只需要现场工控机 Web 界面的客户。Vue 静态文件可由 device_edge 托管，不需要启动 Vite、MySQL 或额外 Node 服务；SQLite 内嵌于 device_edge 进程。

只有一个 Python 服务

工控机只运行一个 Python 后端：device_edge。共享内存读取一次后在进程内复用和广播，不再增加第二个本地服务。

模拟器退出正式链路

现有模拟写入程序仅保留为开发工具。生产启动时必须连接 C++ 已创建的共享内存，未就绪时只报告错误，不创建或写入实时数据内存。

SQLite 是当前范围

SQLite 内嵌于 device_edge，不增加数据库服务进程。具体数据表、保留周期与同步队列设计暂不在本轮确定。

方案 B：本机显示 + 多用户远程管理

适用于需要本机操作，同时希望在办公室或其他终端集中查看、远程控制多台设备的客户。每台工控机本地仍然只有一个 device_edge 服务；指定的一台中心主机单独运行总控服务，负责接收与路由。

客户差异通过配置实现

仅本机客户关闭总控连接；多端客户启用 device_edge 内的上传与远程命令模块。前端和现场主流程无需变更。

总控是单独进程

总控服务部署在指定中心主机，不部署在每台工控机上。它接收上传、维护设备路由并转发远程命令，但不直接访问共享内存。

当前阶段边界

本阶段引入 SQLite，但具体历史、告警、审计与断网补传的数据表尚未定稿。总控不可用时，本机展示与控制仍可工作。
