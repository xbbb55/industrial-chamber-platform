工业试验箱平台：生产环境数据与控制流程

蓝色为设备数据上行，红色虚线为控制指令下行，绿色虚线为执行结果回传。每台工控机保留本地数据库；服务端数据库用于统一管理、长期归档和跨设备查询。

实时数据上行控制指令下行执行结果回传写入存储

工控机本地数据库：该设备的采集源

边缘服务从共享内存读到稳定快照后，先写本地库。它支持现场历史查询、断网持续采集、待上传数据排队与网络恢复后的补传。

服务端数据库：全局权威查询库

保存多台工控机汇总后的历史、告警、试验任务、用户权限与完整指令审计。Redis 仅用于最新状态、在线心跳和短期队列，不能作为唯一存储。

用户可见路径

用户界面始终只访问总控 API 和 WebSocket；现场维护工具可在授权网络内查询该工控机本地数据库，但不能绕过总控执行远程调度。

本地库建议表

telemetry_snapshot（实时/历史快照）、alarm_event（本地告警）、command_execution（命令执行结果）、sync_outbox（待上传事件及重试次数）。保留策略可按现场容量设置，例如原始数据保留 30–90 天。

服务端库建议表

edge、device、telemetry_history、alarm、command、command_result、user、audit_log。历史采样数据建议按日期或月份分区，便于归档与报表查询。

同步规则

本地入库成功后才生成 Outbox 记录；上传成功才标记完成。服务端按唯一键幂等写入，重复上传只更新接收状态，不重复生成历史或告警。

指令规则

服务端先记录指令，再推送/供边缘服务拉取；工控机执行后本地记录结果并回传。指令必须带 command_id、目标设备、操作人、时间和执行状态。

说明：本图为生产目标架构。当前 Demo 的服务端 Python 内存字典不能作为生产唯一存储；在部署数据库前，至少应保留本地落库、可靠上传、服务端幂等写入这三项能力。
